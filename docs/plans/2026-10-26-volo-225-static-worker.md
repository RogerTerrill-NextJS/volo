# VOLO-225 — Minimal static-only worker

VOLO-224 is merged. Register `/sw.js` at `/` in production using the existing root layout and a small client effect. No framework, push permission, sync queue, offline pages or write fallback. Only exact same-origin queryless GET icon requests are cacheable: `/pwa/icon-192.png`, `/pwa/icon-512.png`, `/icon.svg`, `/apple-icon.png`. Exclude navigation, RSC/prefetch, authorization/range requests; fetch icons without credentials and accept only successful nonredirected basic image responses without private/no-store/cookie-vary policy. Manifest and worker remain network-only.

Use versioned `volo-static-` caches, prefill on install, skip waiting/claim only because worker handles public icons, delete old owned caches on activation. Logout POST to exact same-origin `/auth/logout` (optional trailing slash) schedules owned-cache deletion through `waitUntil`, never `respondWith`; leave the existing server auth flow intact. A generation counter and serialized cache mutations prevent pre-logout in-flight fetches from repopulating caches. New post-logout requests may cache public icons again; no private state is cached. Offline writes simply fail on the network, with no replay or synthetic success.

1. Add focused behavior tests running the actual worker script in a minimal VM CacheStorage/event fixture. Verify exact allowlist, credential-free fetch, exclusions, unsafe response refusal, offline icon hit/network miss, version cleanup, logout and in-flight race; observe red before implementation.
2. Implement worker/registration, exact Proxy exception and revalidation/security headers. Add `/sw.js`/lookalike cases to existing matcher regression. Extend existing compiled Proxy HTTP fixture (not a new harness) for worker bytes/headers, assets skipping Auth and root registration; keep existing privacy checks.
3. Run targeted worker/Proxy tests, compiled HTTP fixture, types/lint. Use its owned local browser mode to inspect actual registration/cache in Chrome if possible. Record mobile Safari/Chrome install/update/standalone journey as device checks for VOLO-92, not inferred passes. Fresh final review, commit/push/create PR; no hosted data changes or production publish.

Review focus: no private interception/cache, query/header/response exclusions, version/update behavior, logout/cache mutation race, registration failure leaves app usable. Bump worker cache version whenever allowlisted icon bytes change; no app-shell caching means new page/API code always comes from network.
