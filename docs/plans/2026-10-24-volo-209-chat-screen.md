# VOLO-209 chat screen implementation plan

Build `/messages/[conversationId]` on VOLO-208's ordinary-session history and guarded send action. Render only that minimal authorized history DTO: escaped plain text, sender labels, chronological UTC timestamps and bounded older-page navigation. Keep flight/pilot details behind the existing separately authorized connection page. Add list links to existing conversations; creating/opening a conversation from an accepted request remains VOLO-211, live delivery VOLO-210.

1. Write failing tests for composer feedback: bind exact confirmation to submitted UUID/conversation; rotate UUID and clear text only on success; preserve exact normalized text/UUID on uncertain confirmation; deny further edits while retrying the same payload; sanitize all errors. Add a pure composer-state module and a thin server action wrapping sendMessage, with router refresh only after confirmed sends.
2. Add the guarded page, loading state, chronological escaped message list, latest/older links, explicit refresh and empty/missing/error/closed states. Render composer only on latest writable history. The client form uses the server action for progressive enhancement and handles hydrated transport errors by preserving the same payload/UUID for an explicit retry. Pending submission blocks repeat sends; feedback is announced and focused. No browser/server message cache or optimistic message store.
3. Extend the existing real-session fixture to invoke the actual page composer. Verify both participants and stranger/admin denial, safe plain text, latest/older/invalid pages, closed/private history, native and fetched sends, uncertain retry identity, profile-independent approved connections, and read outages. Reuse local owned resources; no hosted writes.
4. Inspect actual desktop and 320px mobile UI, keyboard/focus and pending/error/retry/closure behavior. Run targeted unit/TypeScript/lint/boundary checks and targeted real-session cases; get a fresh whole-change review, resolve findings, commit/push and create/attach PR.

Review focus: session revocation and stale writable state; lost action transport after a committed send; payload identity across retries; duplicate submits; supplementary Unicode counting; safe multiline/long-word rendering; loading/error and older-page navigation without accidental sends. Full suite and hosted deployment checks are outside this ticket's local verification.
