Design: `public.notifications` stores a server UUID, recipient membership FK, one of three event types, a canonical event key, exactly one typed request/message FK, server creation time and initially null read marker. No copied message body, actor/profile/post text, arbitrary URL, mutable unread counter, generic bus, delivery worker or public writer. Recipient/event-key uniqueness deduplicates retries. Request receipt/acceptance identity includes the existing server status_changed_at so eligible same-record resubmission and later acceptance remain distinct; message identity uses its immutable UUID. An unexposed private persistence trigger derives/validates the recipient and key from the source, checks the appropriate request state and active recipient under lock, and rejects invalid target combinations or updates. Source rows remain retained with restrictive FKs.

Only the current active recipient can SELECT, including counts/embedded reads; administrators have no bypass. Anonymous/member/service-role direct writes and service-role reads are closed. The private schema/function is not executable by application roles. There is no automatic generation/backfill or mark-read mutation in this ticket; owning SQL operations can insert through the persistence contract in VOLO-220. Target references never grant target visibility.
