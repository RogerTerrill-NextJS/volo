# VOLO-209 — Accessible chat and closed history

Based on merged VOLO-208 (`4837933`). `/messages/[conversationId]` independently verifies page access and reads the existing participant history DTO. The conversation list now links to this screen. Flight/pilot context remains behind the existing separately authorized flight connection page; a retained conversation never grants current private flight access.

Messages render as escaped React text, preserving newlines and wrapping long words. Each chronological list item identifies You/Other pilot and a server-formatted UTC timestamp with machine-readable dateTime. Thirty-message pages use the existing stable cursor. Older pages are read-only and link to latest messages to reply. Missing/invalid/error/empty/loading states are neutral, and no unapproved profile/contact data is loaded. Closed or currently unverifiable send authority shows retained history without a composer.

The labeled composer supports native progressive enhancement through the guarded server action, plus hydrated submission with explicit transport-error handling. Pending sends block repeated submission and editing. Exact confirmed success clears text, rotates the UUID, announces/focuses feedback, and refreshes persisted history. Uncertain outcomes retain the normalized body and UUID in a read-only draft with an explicit Retry same message button. Refreshing history preserves that retry state. Access denial removes the send button. Character counting uses Unicode code points; Enter inserts a newline rather than submitting. Nothing automatically resends or copies messages into another store, cache or optimistic timeline.

The page deliberately uses the existing VOLO-208 sender/origin/session/RPC checks. This ticket adds no database migration, accepted-request opening mutation, realtime subscription, receipt or notification. Accepted-request entry is VOLO-211; live delivery is VOLO-210.
