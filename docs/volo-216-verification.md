# VOLO-216 — Moderation controls and hidden-flight feedback

Base: merged VOLO-215 (`972cb7c`). `/admin/flights` exposes its existing bounded active-admin overview and audited hide operation. Each post has escaped flight/owner IDs, route/departure, visibility/lifecycle, notes and recorded moderation reason/time. UUID pagination, empty/invalid/unavailable/denied states and administrator navigation follow the member-administration pattern. Flight detail links administrators to moderation.

Every unhidden post has a required reason and explicit confirmation explaining request/message closure and retained history. Native and hydrated forms use per-target permalinks and exact-target/timestamp/closed-status confirmation. Pending inputs are locked. Invalid input remains editable; denied or uncertain results freeze resubmission until an explicit cursor-preserving GET checks status. Confirmed results refresh the existing page; no optimistic success, automatic mutation retry, unhide or delete control is introduced.

Owners see a hidden notice on retained flight detail. Cancelled request participants see the same moderation explanation in closed history while their permitted history/conversation links remain available. A new ordinary-session scalar RPC reveals only a boolean to the current active owner or requester with cancelled history; unrelated administrators/members, disabled/unadmitted viewers and unknown targets receive false. The query validates the result and rechecks identity/membership. Flight RLS remains unchanged, so a requester cannot recover hidden post details or the moderation reason. Cancellation feedback no longer attributes every flight cancellation to the posting pilot.
