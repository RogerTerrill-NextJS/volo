# VOLO-206 — Participant, sender and closed-state message permissions

Based on merged VOLO-205 (`a4e031f`). `send_conversation_message(conversation UUID,message UUID,body text)` is an authenticated-session-only RPC. Sender identity comes exclusively from auth.uid(); no sender argument, direct table mutation grant or service-role RPC bypass exists. It validates the existing 1–4,000-character nonblank bound and uses fixed errors rather than database row details.

The RPC follows flight → request → conversation locking, holds both current active membership rows, and checks the existing accepted/open/current-PRIVATE connection plus unclosed conversation. VOLO-205's persistence trigger remains an additional defense. An exact conversation/sender/body retry under the same message UUID returns its original UUID/timestamp confirmation without another row or event. Mismatched reuse cannot overwrite or disclose another record. All sends, including retry confirmations, require current writable state; authorized closed history stays available through the existing SELECT RLS.

`supabase_realtime` publishes only protected message INSERT events. DELETE/UPDATE/TRUNCATE and unrelated tables are excluded. The migration rejects an unexpected existing shared publication rather than changing another stream's delivery semantics. Supabase documents that INSERT/UPDATE delivery uses SELECT RLS, whereas deleted rows cannot be authorized after removal ([official Postgres Changes guide](https://supabase.com/docs/guides/realtime/postgres-changes)). The same active-participant history policy therefore governs direct and Realtime row access without granting live PRIVATE flight visibility.

No screen, conversation list, broadcast/presence flow, receipt, notification or application/server/service-worker message cache is introduced. VOLO-208 must wire this RPC through the existing verified session/origin/input/no-store foundation and render bodies as escaped text. VOLO-210 owns the UI subscription lifecycle; receiving an event never grants future sending authority.
