# VOLO-208 — Guarded message sending and history reads

Based on merged VOLO-207 (`52942af`). `sendMessage(previous, form)` enters the existing action mutation boundary on every call: verified origin, current active member, bounded form parsing and strict application fields. `conversation_id`, `message_id` and `body` are the only fields accepted. Sender/timestamp/ownership cannot be selected by the form, and existing connections do not require profile completeness. Ordinary session RLS checks the actual participant before the existing locked `send_conversation_message` RPC checks both active memberships and the current accepted/open/private-flight relationship.

Input is bounded to 1–4,000 nonblank Unicode code points, rejects ill-formed text/NUL and normalizes CRLF/CR to LF to keep native and fetched action retry payloads consistent. All other text is preserved. Only exact UUID/conversation/sender/timestamp confirmations become `sent`; no body or raw provider data appears in the result. Definitive input/access denials are distinct from `send_unconfirmed`. A transport error or malformed confirmation never triggers an automatic resend. VOLO-209 must retain the same UUID/conversation/body for an explicit retry and generate a new identity only for a new logical message.

`getConversationHistory(conversationId, before)` reads 30+1 messages through ordinary session RLS. Timestamp and UUID descending select the latest/older page; the returned visible page is chronological. Cursors preserve six fractional digits and strictly validate before entering filter syntax. Conversation bindings are checked before and after the message read, and current viewer access is checked before returning. The minimal DTO contains conversation/request/counterpart identity and messages, without flight details or contact/profile data. `sendStatus` distinguishes available, closed and temporarily unverifiable authority. The actual send RPC always rechecks authority; a readable page is never a send grant.

Closed/withdrawn/cancelled/private-recipient-removed conversations retain permitted participant history. A disabled counterpart closes sends without removing an active participant's readable history. A disabled viewer cannot read. No new database migration, message store, production API route, composer, presentation or subscription is added. VOLO-209 owns the accessible chat screen and VOLO-210 the realtime UI.

## Verification

- New module tests failed before implementation, then passed. A native/fetched newline regression also failed before LF canonicalization and passed after it.
- Review identified a persisted-text mismatch: PostgreSQL accepts U+FEFF as nonblank, while JavaScript trim considers it blank. A read-only query in the owned disposable PostgreSQL database confirmed this. History and list regression tests reproduced unavailable results before the correction. Persisted rows now use bounded well-formed text validation independent of stricter send-input blank checks; an invisible preview has a neutral fallback. Both regressions passed after the correction.
- All 18 targeted send/history/list/mutation guard unit checks passed. Covers payload shape and Unicode limits, sender binding, exact confirmations, sanitized uncertain outcomes with one RPC attempt, denied/changed sessions, retained history and writable authority, stable timestamp ties/keysets and malformed records.
- The initial targeted real-Auth flight-interest group passed all 48 scenarios and owned cleanup. Added cases exercised the actual native/fetched send action, multiline retry deduplication, 4,000 supplementary Unicode characters, forged identity and wrong-origin denial, unprivileged admin/disabled/nonparticipant denial, committed-response loss/malformed confirmation followed by explicit same-identity retry, private closed history, 34-message paging, read outage, disabled counterpart and mid-read viewer revocation.
- All three focused send/history scenarios passed again with the final persisted-text correction and owned cleanup, including a real authenticated RPC U+FEFF message and rendered conversation-list fallback.
- Route generation, TypeScript, focused ESLint, diff checks and server/client boundary checks passed. The boundary fixture explicitly proves the new history and send policy cannot enter Client Components; HTML/RSC/JSON/headers/bundles expose no private configuration markers. Independent review found the persisted-text issue above; it was corrected with failing-then-passing regressions.

Only owned fictional local accounts/data were used. Full-suite, hosted Deploy Preview and production verification were not run. No hosted migration/data/accounts/email/settings changes or production publication occurred. Preview verification and any later user-requested production release remain separate.
