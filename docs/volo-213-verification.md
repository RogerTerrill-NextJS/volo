# VOLO-213 — Guarded member administration and audit writes

Base: merged VOLO-212 (`4add713`). This is VOLO-85's server-side step. VOLO-214 owns the member controls and operator recovery guidance. No account deletion, role promotion, reactivation, Auth credential change or token-management operation is exposed.

`admin_member_overview` requires an authoritative active-admin membership and returns at most 51 UUID-ordered rows. The server-only query checks current administrator identity before and after the read, validates order/metadata, returns 50 rows with a UUID cursor, and excludes account emails, Auth data and unexpected provider fields. The projection contains membership identity, display name, role/status, creation/disable time and a reason excerpt of at most 500 characters with an explicit truncation flag. Older schema-valid reasons and timestamps remain readable; new disables use stricter input validation.

`disableMember` uses the existing origin/session/role/bounded-form guard. Only target UUID, explicit disable confirmation and a required 1–500-character reason are accepted. The ordinary-session `admin_disable_member` RPC locks actor/target memberships in UUID order and rechecks active-admin authority under lock. Self-disable is blocked. An admin may disable another admin; concurrent cross-disables preserve an active administrator. Membership update and append-only audit insertion share one transaction. Actor, action, target, timestamp and normalized reason are bound server-side. An audit insert failure rolls back the disable.

Repeated disables return the existing timestamp without rewriting reason or inserting another audit row. Ambiguous/malformed responses return `disable_unconfirmed`, never automatic retries or unverified success. Non-admin/disabled callers cannot use the RPC or overview, and cannot read audit rows. Direct authenticated audit writes and service-role RPC bypass are denied. Disabling retains Auth identity, profiles, flights and other existing records; current membership checks revoke subsequent protected reads/actions for retained sessions.

- Actual local Auth integration passed all three scenarios with native/fetched Server Actions and ordinary authenticated RPCs: active-admin overview/action guards, retained-session revocation with preserved Auth/profile/flight data, and ambiguous-result/idempotent/concurrent behavior. All owned resources were cleaned up.

A failing unit regression reproduced it; projection now matches the existing schema contract. Independent review found the same compatibility issue for legacy long/newline-only reasons. Failing regressions preceded bounded reason projection and a truncation flag; final SQL/unit/real-session checks passed with those fixes.

The real-session production fixture compiled the actual query/action modules. CI now includes the existing runner's member-admin mode and the targeted unit cases; no second Auth harness was created. The full suite, unrelated SQL/concurrency and browser presentation checks were not run under the MVP policy; no production UI changes belong to this step.
