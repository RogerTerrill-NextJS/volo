# VOLO-210 — Live conversation updates

Based on merged VOLO-209 (`7ca73ae`). Latest writable conversation pages subscribe through the ordinary authenticated browser client to INSERT events filtered to their conversation UUID. Confirmed stream readiness and SDK reconnect/token handling drive a small live status. Valid matching events coalesce a server history refresh; socket bodies never enter a message store or render directly. Rejoin and browser resume also catch up persisted history.

Older pages and closed conversations do not mount the live watcher. Navigation and identity changes remove only its owned channel and auth listener, cancel pending invalidations, and ignore late callbacks. Existing server authorization, message RPC checks, and Realtime RLS remain authoritative. `/messages` paths now explicitly use the existing private response policy, including anonymous requests.

One viewer-bound, in-memory form draft lives in the conversation layout so automatic refresh errors do not discard unsent text or the UUID/body of an uncertain send. Try again refreshes within that layout. Confirmed closure, missing access, or identity loss clears the draft. There is no message cache, optimistic timeline, automatic resend, browser storage, new publication, or database migration.
