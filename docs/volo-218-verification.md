# VOLO-218 — Report/support entry and founder handling

Base: merged VOLO-217 (`afb9440`). Authorized pilot profiles, flight detail and retained message rows now expose contextual report links. `/reports` explains the beta path or renders one report form. Only target kind/UUID and a canonical report UUID enter the URL; message bodies, target snapshots and reasons are not copied into links. Required reasons use the existing ordinary-session guarded intake and 2,000-Unicode-character limit.

Native and hydrated submissions preserve exact report identity. Pending controls lock; confirmed feedback supplies the reference and removes the form. Uncertain/denied results freeze sends and offer an explicit GET status check. Receipt recovery is bounded to one report and always filters the current reporter, including administrators, with before/after identity/role/access checks. Current active reporters can recover existing receipts after target visibility changes. No GET submits or automatically retries.

`/admin/reports` uses an independently current-admin-only bounded query, UUID pagination and escaped report descriptions/reference IDs. The view includes handling guidance and links to existing member-disable/flight-moderation controls; it adds no private-conversation lookup, status engine or automatic action. `docs/founder-report-handling.md` records manual triage, evidence/access limits, action verification, restricted founder notes, retained data and release boundaries. The user's explicit MVP decision remains reports and founder-admin handling only, with no personal blocking.
